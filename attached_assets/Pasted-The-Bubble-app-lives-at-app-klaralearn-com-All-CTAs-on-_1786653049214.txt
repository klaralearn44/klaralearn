1. Pre-Rendering (Critical — Do This First)
This is likely a React or Next.js SPA. Google's JavaScript renderer is unreliable and slow. Every page must render real HTML at build time.

If React + Vite:

Create src/entry-server.tsx as the SSR render entry
Create scripts/prerender.mjs that builds an SSR bundle, discovers all routes from data files, renders each with renderToString, and writes dist/[route]/index.html with the full rendered HTML injected
Every route must produce a standalone HTML file — /subjects/maths/index.html, /tutors/[slug]/index.html, /location/london/index.html, etc.
The pre-render script must also inject per-page <title>, <meta name="description">, <link rel="canonical">, and all Open Graph tags into the <head> of each file
If Next.js:

Use getStaticProps + getStaticPaths for all dynamic routes (tutor profiles, subject pages, location pages)
Use generateMetadata (App Router) or getServerSideProps (Pages Router) for metadata
Ensure ISR (Incremental Static Regeneration) is set up for tutor profiles so new tutors appear without full rebuilds
The test: curl -s https://klaralearn.com/subjects/maths | grep "<h1>" must return actual content. If it returns an empty <div id="root">, pre-rendering is not working and Google will not index your pages.

6. Internal Linking Strategy
Internal linking is how PageRank flows through your site. Follow these rules:

Every tutor profile must link to their subject page(s) and location page
Every subject page must link to: related subjects, relevant blog posts, the homepage, and a "Browse all tutors" CTA
Every location page must link to: subjects available in that city, the homepage, and nearby cities
The homepage must link to: all primary subject pages, top 3–5 location pages, the blog, and How It Works
Every blog post must link to: at minimum 2 relevant subject pages, 1 location page, and 1 related blog post
Use exact-match or close-match anchor text: "11 Plus tutors in London", not "click here"
Never use window.location.href or plain <a href> for internal navigation in a React/Next.js app — always use the router's <Link> component to preserve SPA behaviour and avoid full page reloads

8. AEO — Answer Engine Optimisation
AEO is about getting KlaraLearn's content into Google's featured snippets and People Also Ask boxes. Rules:

For featured snippets:

Identify the exact question the searcher asks (e.g. "How much does 11 Plus tutoring cost?")
Answer it in the first 40–60 words of the relevant section, directly and completely
Use the question as the H2 or H3 heading immediately above the answer
Format: Definition box style (one clear paragraph), or a numbered list for "how to" questions
For People Also Ask:

Every subject page and every blog post must include a visible FAQ section
Each question in the FAQ section must exactly match or closely mirror real PAA questions from Google (research these for each keyword)
Apply FAQPage JSON-LD schema to every FAQ section
Questions should be written from the parent's perspective: "How many hours a week should my child have 11 Plus tutoring?", "Is online tutoring as effective as in-person for 11 Plus?"
Snippet-ready content formats:

Tables (e.g. "11 Plus Tutoring Cost Comparison" table: Local UK tutor vs KlaraLearn tutor)
Numbered lists (e.g. "5 things to look for in an 11 Plus tutor")
Definition paragraphs (e.g. "What is the 11 Plus? The 11 Plus is a selective entrance examination taken by Year 5 and Year 6 pupils in England...")
9. GEO — Generative Engine Optimisation
GEO is about ensuring AI systems (ChatGPT, Perplexity, Google Gemini, Claude) reference KlaraLearn when parents ask tutoring questions. AI models prioritise:

Entity clarity: Every page must make it 100% clear what KlaraLearn is, who it serves, and what it does. The homepage and About page must state this in plain, unambiguous language in the first paragraph. AI systems read this to build their knowledge graph entry for KlaraLearn.

Authoritative factual content: AI models cite sources that state facts accurately and cite their reasoning. Each article should include:

Accurate statistics about UK school exams (sourced from GOV.UK, exam boards)
Pricing data compared to industry averages
Expert commentary from named tutors on KlaraLearn
Brand entity establishment: Ensure the name "KlaraLearn" appears consistently across all pages, in schema markup ("name": "KlaraLearn"), in the Open Graph title, and in the page title. Consistency of name = stronger entity recognition by AI. The canonical domain https://klaralearn.com must appear in every canonical tag and schema URL field.

Structured "about" content: Include a clear, structured About page at https://klaralearn.com/about/ with:

What KlaraLearn is (one sentence)
Who it's for (parents of UK secondary school students)
How it works (3 steps)
How tutors are vetted
Company background and mission
Citations and E-E-A-T (Experience, Expertise, Authority, Trust):

Every tutor profile should show verifiable credentials
Every blog post should have a named author with a byline and bio
Link to authoritative external sources (GOV.UK, exam board websites) from relevant articles — this signals to AI that KlaraLearn's content is grounded in real-world, verifiable information

11. Keyword Integration Instructions
When you receive the keyword sheet, apply keywords as follows:

Priority	Placement
Primary keyword	H1, <title>, first 100 words of body, meta description, URL slug
Secondary keywords	H2/H3 subheadings, image alt text, internal link anchor text
Long-tail keywords	FAQ questions, blog post titles, body paragraphs
Location + keyword combos	Location page H1s and meta, tutor profile metadata
Do not keyword-stuff. Each keyword should appear naturally and be surrounded by relevant supporting content. Google's Helpful Content system penalises thin, keyword-heavy pages.
